# Reading Journey Skill

## Purpose

维护个人长期读书档案。

核心原则：

- 一本书始终对应一个 HTML 文件。
- 每次阅读都追加为一次独立的阅读记录。
- 不删除、不覆盖历史阅读记录。
- 自动维护阅读次数、已读页数、阅读进度、总阅读时间和阅读状态。
- 所有书籍文件存储在 `books/`。
- 新书必须基于 `templates/book-template.html` 创建。
- 每次完成操作后，将更新提交到 GitHub 仓库。

---

# Mode Detection

根据用户请求自动判断：

1. **新建书籍**：书籍尚不存在。
2. **更新阅读记录**：对应书籍 HTML 已存在。
3. **完成阅读**：用户明确表示读完，或最后阅读记录达到全书结束页。
4. **补充读后感**：书籍已完成，但尚未填写最终读后感。

如信息不足，优先询问缺失字段，不擅自编造。

---

# Mode 1：新建书籍

首次创建一本书时，收集：

- 书名（必填）
- 作者（必填）
- 全书总页数（必填）
- 为什么开始读这本书（必填）
- 开始阅读日期（必填）
- 书籍封面（可上传图片；如无封面则使用占位图）

初始化数据：

- 阅读状态：📖 阅读中
- 阅读次数：0 次
- 当前已读页数：0 页
- 总阅读时间：0 分钟
- 阅读进度：0%

执行步骤：

1. 检查 `books/` 中是否已有同名书籍。
2. 如不存在，读取 `templates/book-template.html`。
3. 将模板占位符替换为书籍信息。
4. 将封面保存或引用为可长期访问的图片资源。
5. 创建 `books/{书名}.html`。
6. 提交 GitHub。
7. 告知用户书籍档案已创建。

禁止创建重复书籍。

---

# Mode 2：新增阅读记录

每次阅读必须记录：

- 书名
- 开始页码
- 结束页码
- 已读章节
- 本次阅读时间
- 本次阅读内容概述
- 金句摘抄
- 每条金句对应的个人感悟
- 本次阅读感悟

## 页码规则

用户采用方式 A：

开始页码 + 结束页码。

本次阅读页数：

`结束页码 - 开始页码 + 1`

校验：

- 开始页码不得大于结束页码。
- 页码不得小于 1。
- 结束页码不得超过全书总页数。
- 如与历史阅读范围明显重叠，提醒用户确认；不要默默重复累计。

## 阅读次数

读取已有阅读记录数量。

新记录编号：

`已有记录数量 + 1`

格式：

- 第 01 次阅读
- 第 02 次阅读
- 第 03 次阅读

始终使用两位数字。

## 已读页数与进度

默认累计方式：

- 如果阅读记录连续且无重叠：累计本次阅读页数。
- 如存在重叠：按实际唯一页码计算，避免重复统计。

阅读进度：

`已读唯一页数 / 全书总页数 × 100%`

显示百分比时保留整数；内部数据可保留更高精度。

进度最大不得超过 100%。

## 阅读时间

统一转换为分钟后累计。

支持用户输入：

- 45分钟
- 1小时
- 1小时30分钟
- 90分钟

HTML 展示规则：

- 小于 60 分钟：XX 分钟
- 大于等于 60 分钟：X 小时 Y 分钟

## 新增阅读记录 HTML 结构

每次记录必须包含：

- 阅读日期
- 开始页码 — 结束页码
- 本次阅读页数
- 已读章节
- 本次阅读时间
- 内容概述
- 金句摘抄
- 每条金句的个人感悟
- 本次阅读感悟

金句与感悟必须一一对应。

如果没有金句，明确显示“本次无金句摘抄”，不要编造。

# HTML 更新规则

更新现有书籍时：

1. 先读取完整现有 HTML。
2. 保留所有已有内容。
3. 只更新指定标记区域。

## BOOK_METADATA

更新：

- 阅读状态
- 必要时完成日期

## READING_STATS

更新：

- 当前已读页数
- 阅读次数
- 总阅读时间
- 阅读进度百分比
- 进度条宽度
- 阅读状态

## READING_TOC

新增对应阅读记录导航链接。

格式示例：

`01 · 第一次阅读`

链接到：

`#reading-01`

## READING_LOGS

将新的阅读记录追加在已有记录之后。

不得修改历史阅读记录，除非用户明确要求更正。

每条记录使用唯一 ID：

`reading-01`
`reading-02`
`reading-03`

## FINAL_REFLECTION

阅读完成前保持隐藏或占位。

阅读完成后显示完整区域。

# Mode 3：完成阅读

满足以下任一条件时触发：

1. 用户明确表示“读完了”。
2. 最后有效阅读页码达到全书总页数。

自动更新：

- 阅读状态：🎉 已读完
- 阅读进度：100%
- 当前已读页数：全书总页数

然后收集：

- 完成阅读日期
- 全书读后感

如果用户暂时没有读后感：

- 仍然可以标记为已读完。
- 保留“读后感待补充”状态。
- 后续允许单独补充。

---

# Mode 4：补充读后感

读取对应已完成书籍。

更新：

- 完成阅读日期（如之前为空）
- 全书读后感

不得修改已有阅读记录。

---

# 数据准确性原则

必须：

- 先读取旧 HTML，再更新。
- 不依赖记忆猜测历史数据。
- 不重新编号历史阅读记录。
- 不删除用户过去的内容。
- 不编造日期、页码、阅读时间、感悟或读后感。
- 计算前检查已有统计数据与历史记录是否一致。
- 如发现不一致，以历史阅读记录为基础重新计算，并说明修正。

仓库：

`yiii09/reading-notes`

每次修改：

1. 获取文件最新版本。
2. 执行更新。
3. 创建明确的 Commit Message。

Commit 示例：

- `feat: create reading journal for 原子习惯`
- `docs: add reading session 03 to 原子习惯`
- `docs: complete reading journal for 原子习惯`
- `docs: add final reflection to 原子习惯`
